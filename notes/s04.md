# s04: Subagent 知识点

> 格言：*"大任务拆小，每个小任务干净的上下文"*

---

## 核心思想

messages 越来越胖，脏活的中间过程永久污染父 Agent 上下文。父 Agent 问"用什么测试框架"，子 Agent 可能要读 5 个文件，但父 Agent 只需要一个词："pytest"——那 5 个文件的内容不应该留在父 Agent 的上下文里。

**解法：子 Agent 用独立 `messages=[]`，干完活只返回摘要，自身上下文丢弃。**

---

## 架构图

```
父 Agent                              子 Agent
messages=[很长的历史...]              messages=[]  ← 全新干净
        |                                   |
        | 调用 task 工具，传 prompt           |
        |  ──────────────────────────────>  |
        |                             自己跑循环
        |                             读文件、跑命令
        |                             可能 30 轮工具调用
        |                                   |
        |  <──────────────────────────────  |
        | 收到一段摘要文本                    | 上下文全部丢弃
        | 作为普通 tool_result 塞回去
```

---

## 三个关键设计

### 1. 两套工具列表，职责分离

```python
CHILD_TOOLS = [bash, read_file, write_file, edit_file]  # 4个基础工具
PARENT_TOOLS = CHILD_TOOLS + [task]                      # 基础工具 + task
```

子 Agent 没有 `task` 工具，防止子 Agent 再派孙 Agent 无限递归。

两套 system prompt 也不同：
- 父 Agent：`"Use the task tool to delegate..."` — 负责规划和接收摘要
- 子 Agent：`"Complete the given task, then summarize your findings."` — 负责执行并总结

用同一个 system prompt 会造成混乱——子 Agent 可能试图调用它根本没有的 `task` 工具。

### 2. for range(30) + break，不是 while True + return

```python
def run_subagent(prompt: str) -> str:
    sub_messages = [{"role": "user", "content": prompt}]
    for _ in range(30):          # ← 安全上限，保证函数一定返回
        response = client.messages.create(...)
        sub_messages.append(...)
        if response.stop_reason != "tool_use":
            break                # ← break 不是 return
        ...执行工具...

    return "".join(b.text for b in response.content if hasattr(b, "text")) or "(no summary)"
```

用 `break` 不用 `return` 的原因：不管是正常结束还是跑满 30 轮强制停，都在循环外统一拿最后一次 response 返回。

如果在循环内 `return`，跑满 30 轮的情况会漏掉——循环自然结束时没有 `return`，函数返回 `None`，父 Agent 收到 `None`。

### 3. task 工具不进路由表，单独处理

```python
if block.name == "task":
    desc = block.input.get("description", "subtask")
    output = run_subagent(block.input["prompt"])   # 手动取需要的字段
else:
    handler = TOOL_HANDLERS.get(block.name)
    output = handler(**block.input)                # **kw 解包
```

路由表用 `**block.input` 解包，要求函数签名和 schema 完全匹配。

`task` 的 schema 有两个字段：`prompt` 和 `description`，但 `run_subagent` 只接受 `prompt`。如果放进路由表，解包时 `description` 没地方放，直接 TypeError。

所以单独处理，手动取需要的字段。

## description 字段的作用

`task` 工具有 `prompt` 和 `description` 两个字段：

```
prompt:      "Read all .py files and find what testing framework is used..."
description: "explore testing setup"
```

- `prompt`：完整指令，传给子 Agent 执行
- `description`：模型自己填的一句话摘要，纯粹给开发者看日志用

对模型执行没有任何影响。运行时终端输出：
```
> task (explore testing setup): Read all .py files and find what testing...
```

`description` 是 prompt 的压缩/缩写，让日志一眼看出这个子任务在干什么。

## 摘要提取

```python
return "".join(b.text for b in response.content if hasattr(b, "text")) or "(no summary)"
```

- `response.content` 是列表，可能有 `TextBlock`（有 `text` 属性）和 `ToolUseBlock`（没有）
- `hasattr(b, "text")` 过滤掉 ToolUseBlock，只取模型写的文字
- `or "(no summary)"` 兜底，防止模型没输出任何文字时返回空字符串

**靠 system prompt 引导模型写总结，靠代码兜底边界情况。不要只靠 prompt，也不要期望模型 100% 听话。**

### 子 Agent 的总结不是"重新归纳"

子 Agent 最后一轮 `stop_reason = "end_turn"`，说明它认为任务完成，这一轮不调工具，直接写了一段文字。这段文字就是摘要，不是重新过上下文归纳出来的。

原因：`sub_messages` 每轮都在累积，模型一直都能看到完整历史：

```
sub_messages = [
    {role: "user",      content: "找测试框架"},            # 初始任务
    {role: "assistant", content: [ToolUseBlock...]},       # 第1轮：调 bash
    {role: "user",      content: [tool_result...]},        # 第1轮结果
    {role: "assistant", content: [ToolUseBlock...]},       # 第2轮：调 read_file
    {role: "user",      content: [tool_result...]},        # 第2轮结果
    ...
    {role: "assistant", content: [TextBlock("结论是...")] }, # 最后一轮：写总结
]
```

模型写总结时不需要重新读文件，因为所有读到的内容都在 `sub_messages` 里，它一直都知道。这也是为什么子 Agent 上下文丢掉没关系——父 Agent 只需要最后那句结论。
