## 核心知识点

### 1. messages[] 是一切的基础
- 所有历史累积在这个列表里，结构：`[user, assistant, user, assistant, ...]`
- 工具结果以 `role: "user"` 追加——对模型来说，工具结果和用户消息地位相同
- 模型每次看到完整历史，所以"记得"之前做了什么

### 2. stop_reason 是循环的唯一退出条件
| stop_reason | 含义 |
|---|---|
| `"tool_use"` | 模型想调用工具，继续循环 |
| `"end_turn"` | 模型认为任务完成，退出 |
| `"max_tokens"` | token 超限，退出 |

### 3. TOOLS 是结构化的 prompt
- `description`：告诉模型这个工具做什么，影响模型何时选择调用它
- `input_schema`：约束模型输出为 JSON，便于代码解析
- 模型不执行工具，只返回"我要调用 X，参数是 Y"

### 4. 工具调用的数据结构

模型返回的 tool_use block：
```json
{
  "type": "tool_use",
  "id": "toolu_xxx",
  "name": "bash",
  "input": { "command": "ls -la" }
}
```

代码回传的 tool_result block：
```json
{
  "type": "tool_result",
  "tool_use_id": "toolu_xxx",
  "content": "file1.txt\nfile2.txt"
}
```

`tool_use_id` 必须对应，模型才知道哪个结果属于哪次调用。

### 5. Harness vs Agent 的边界
| Harness（我们写的代码） | Agent（模型） |
|---|---|
| 定义工具（TOOLS） | 决定调用哪个工具 |
| 执行命令（run_bash） | 决定命令内容 |
| 管理 messages[] | 决定何时停止 |
| 危险命令过滤 | 规划步骤顺序 |

### 6. 最小实现

```python
def agent_loop(query):
    messages = [{"role": "user", "content": query}]
    while True:
        response = client.messages.create(
            model=MODEL, system=SYSTEM,
            messages=messages, tools=TOOLS,
        )
        messages.append({"role": "assistant", "content": response.content})
        if response.stop_reason != "tool_use":
            return
        results = []
        for block in response.content:
            if block.type == "tool_use":
                output = run_bash(block.input["command"])
                results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": output,
                })
        messages.append({"role": "user", "content": results})
```
