# s05: Skill Loading 知识点

> 格言：*"用到什么知识，临时加载什么知识"*

---

## 核心思想

把所有领域知识塞进系统提示太浪费 token。10 个技能 × 2000 tokens = 20,000 tokens，不管用户问什么，每次对话都要付这个固定成本。

**解法：两层注入。Layer 1 放技能目录（便宜），Layer 2 按需加载完整内容（贵）。**

---

## 两层结构

```
Layer 1 (System Prompt) ── 始终存在，~20 tokens/skill
  - pdf: Process PDF files...
  - code-review: Review code...
  - git: Git workflow helpers...

Layer 2 (tool_result) ── 按需加载，~2000 tokens/skill
  <skill name="pdf">
    # PDF Processing Skill
    ...完整操作指南...
  </skill>
```

**Layer 1 解决"发现问题"**：模型知道有哪些技能、名字是什么，才能精准调用 `load_skill(name="pdf")`。没有 Layer 1，模型只能猜名字，大概率猜错。

**Layer 2 解决"加载问题"**：需要时才把完整内容注入上下文，不用的技能零成本。

---

## 技能文件结构

```
skills/
  pdf/
    SKILL.md
  code-review/
    SKILL.md
  agent-builder/
    SKILL.md
  mcp-builder/
    SKILL.md
```

每个 `SKILL.md` 用 YAML frontmatter 分隔元数据和正文：

```markdown
---
name: pdf
description: Process PDF files - extract text, create PDFs, merge documents.
---

# PDF Processing Skill
（完整内容，~100 行）
```

`---` 之间是 Layer 1 用的元数据，`---` 之后是 Layer 2 用的正文。

---

## SkillLoader

### 启动时扫描所有技能

```python
def _load_all(self):
    for f in sorted(self.skills_dir.rglob("SKILL.md")):
        text = f.read_text()
        meta, body = self._parse_f
        rontmatter(text)
        name = meta.get("name", f.parent.name)   # ← 没有 name 字段就用目录名
        self.skills[name] = {"meta": meta, "body": body}
```

注意：`name` 优先用 frontmatter 里的 `name` 字段，fallback 到目录名（小写）。

### 两个对外方法

```python
# Layer 1 用：返回所有技能的名称和描述
def get_descriptions(self) -> str:
    return "  - pdf: Process PDF files...\n  - code-review: ..."

# Layer 2 用：返回指定技能的完整内容，包在 XML 标签里
def get_content(self, name: str) -> str:
    return '<skill name="pdf">\n# PDF Processing Skill\n...\n</skill>'
```

## 接入 harness：只改两个地方

### 1. 系统提示动态拼入 Layer 1

```python
SKILL_LOADER = SkillLoader(SKILLS_DIR)

SYSTEM = f"""You are a coding agent at {WORKDIR}.
Use load_skill to access specialized knowledge before tackling unfamiliar topics.

Skills available:
{SKILL_LOADER.get_descriptions()}"""   # ← f-string，启动时求值，模型只看到纯文本
```

`get_descriptions()` 在 Python 启动时就跑完了，模型收到的是纯文字描述列表，不知道背后有 SkillLoader。

### 2. load_skill 加入 dispatch map

```python
TOOL_HANDLERS = {
    "bash":       lambda **kw: run_bash(kw["command"]),
    "read_file":  lambda **kw: run_read(kw["path"], kw.get("limit")),
    "write_file": lambda **kw: run_write(kw["path"], kw["content"]),
    "edit_file":  lambda **kw: run_edit(kw["path"], kw["old_text"], kw["new_text"]),
    "load_skill": lambda **kw: SKILL_LOADER.get_content(kw["name"]),  # ← 新增
}
```

`load_skill` 和其他工具地位完全平等，harness 零特殊处理。返回的 tool_result 被模型"内化"为知识。

---

## 数据流

```
用户: "Help me process a PDF"
        ↓
模型看到系统提示里有 "- pdf: Process PDF files..."
        ↓
模型调用 load_skill(name="pdf")
        ↓
TOOL_HANDLERS["load_skill"] → SKILL_LOADER.get_content("pdf")
        ↓
tool_result: <skill name="pdf">...完整指南...</skill>
        ↓
模型读取内容，现在"会"处理 PDF 了
        ↓
按 skill 里的工作流执行任务
```

## 扩展：自动加载高频技能

不改 SkillLoader，只改 SYSTEM 构建逻辑：

```python
# git skill 启动时直接嵌入系统提示，无需模型调用 load_skill
auto_loaded = SKILL_LOADER.get_content("git")

SYSTEM = f"""You are a coding agent at {WORKDIR}.

{auto_loaded}

Skills available (load on demand):
{SKILL_LOADER.get_descriptions()}"""
```

代价：该 skill 的 token 成本变为固定成本。适合极高频使用的技能，其余保持按需加载。
