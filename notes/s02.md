# s02: Tool Use 知识点

> 格言：*"加一个工具，只加一个 handler"*

---

## 核心思想

s01 的循环一行没改。唯一变化：工具从 1 个变 4 个，加了一个 dispatch map 来路由。

**路由表是给我们的代码用的，不是给模型用的。**

- 模型看到的是 TOOLS 列表（工具说明书），决定调哪个工具，返回工具名和参数
- 我们的代码拿着工具名去路由表查对应函数，执行，把结果返回给模型

## 核心知识点

### 1. Dispatch Map（路由表）

```python
TOOL_HANDLERS = {
    "bash":       lambda **kw: run_bash(kw["command"]),
    "read_file":  lambda **kw: run_read(kw["path"], kw.get("limit")),
    "write_file": lambda **kw: run_write(kw["path"], kw["content"]),
    "edit_file":  lambda **kw: run_edit(kw["path"], kw["old_text"], kw["new_text"]),
}
```

- 字典替代 if/elif 链
- key 是工具名（模型返回的 `block.name`）
- value 是对应的执行函数
- `**block.input` 把模型填的 JSON 参数直接解包传给函数

**加新工具只需两步，循环不动：**
1. `TOOL_HANDLERS` 加一行
2. `TOOLS` 加一个 schema

### 2. 模型 vs 代码的分工

| 模型 | 我们的代码 |
|---|---|
| 看 TOOLS 说明书，决定调哪个 | 定义 TOOLS 列表 |
| 返回 `{ name, input }` | 用 name 查路由表 |
| 收到 tool_result，继续推理 | 执行函数，返回结果 |

模型只管"叫名字"，路由表管"找函数"。

### 3. 路径沙箱 safe_path()

```python
def safe_path(p: str) -> Path:
    path = (WORKDIR / p).resolve()
    if not path.is_relative_to(WORKDIR):
        raise ValueError(f"Path escapes workspace: {p}")
    return path
```

- 防止模型用 `../../etc/passwd` 逃出工作目录
- 所有文件操作工具（read/write/edit）都经过这个检查
- 这是权限边界的第一个真实实现，s12 会做得更完整
