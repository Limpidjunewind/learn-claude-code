# s08 - Background Tasks（后台任务）

## 核心洞见
**耗时的 I/O 操作不需要 CPU 一直盯着，扔到后台，主线程继续干活。**
agent 是串行的，但世界是并行的。编译、测试、安装依赖这类任务，等待时间远大于计算时间。

---

## 两层并发结构

```
主线程:   run() → Thread(target=_execute).start() → return task_id  ← 立刻结束
后台线程:                                 _execute() → subprocess.run("pytest") → 等待完成
```

| 层 | 机制 | 负责什么 |
|---|---|---|
| 第一层 | `threading.Thread` | 把"等待"隔离到后台，主线程不阻塞 |
| 第二层 | `subprocess.run` | 真正启动外部程序（有独立 PID） |

`thread.start()` 之后主线程立刻走到 `return`，不等 `_execute` 跑完。

---

## BackgroundManager 数据结构

```python
self.tasks = {}                  # 档案馆：所有任务永久记录，供 check() 查询
self._notification_queue = []    # 收件箱：刚完成的结果，drain 后清空
self._lock = threading.Lock()    # 互斥锁：保护队列的读写安全
```

### tasks vs _notification_queue

| | `tasks` | `_notification_queue` |
|---|---|---|
| 生命周期 | 永久保留 | 取走即清空 |
| 用途 | `check()` 查任务状态 | `drain()` 给 LLM 注入结果 |
| 写入时机 | `run()` 创建时 | `_execute()` 完成时 |

---

## 线程安全：`_lock` 的作用

**竞态条件**：两个线程同时操作同一数据结构，结果不可预期。

**具体场景（去掉锁会发生）：**
```
主线程 drain:    list() 复制完了...
                              ← 后台线程 append 了一条新结果
主线程 drain:    ...clear() 清空  ← 新结果被误删，LLM 永远收不到
```

**加锁后：**
```
主线程 drain:    [锁门] → list() → clear() → [开锁]
后台线程:                 [等门口...]                  → [锁门] → append
```

`with self._lock` 把"复制+清空"变成原子操作，中间不能被打断。

---

## 结果如何回到 LLM

```
后台线程完成
    → _notification_queue.append(result)

主线程下一轮 agent_loop（每次调 LLM 前）
    → drain_notifications() 取出所有通知（可能多条）
    → 拼成字符串塞进 messages
    → LLM 这时才"看到"结果
```

**关键**：不是"完成立刻通知"，而是"下次调 LLM 前顺手注入"。

结果在队列里等着，不会丢，直到被 drain 取走。

---

## 局限与取舍

| 问题 | 原因 | 改进方向 |
|---|---|---|
| LLM 可能忘了任务 | 只靠 messages，context 压缩后消失 | 结合 s07 task 文件持久化 |
| Ctrl+C 杀死后台任务 | `daemon=True`，主进程退出线程强制终止 | 有副作用的任务去掉 daemon |
| 结果可能不完整 | 通知截断 500 字符 | 完整结果在 `tasks` 里（50000 字符限制） |

### daemon=True 的取舍
- **保留**：后台任务无持久化副作用，agent 退出时不想被卡住
- **去掉**：后台任务在写文件/数据库，中途杀掉会数据损坏

---

## 关键术语
- **原子性**：操作要么完整执行，要么完全不执行，不能被中间打断
- **竞态条件**：多线程同时访问共享数据，结果依赖执行顺序，不可预期
- **daemon 线程**：主进程退出时强制终止的线程

---

## s07 + s08 的结合点
- s07：任务状态持久化（不怕 context 压缩）
- s08：任务并行执行（不阻塞主线程）
- **两者组合**：后台任务完成后更新 task 文件 → 即使 context 压缩，进度也不丢
